# 参考实例：插件型宿主（自带插件系统 + 多 Workspace / Session）

> **这是一类宿主的实例，不是流程。** 通用流程见 `SKILL.md`。
> 本文件用**占位符**写成，描述的是「**同时**具备插件化架构与多 Workspace / Session 模型」这一类
> 宿主的接入形状，不含任何具体产品的档案。把你自己的宿主代进 `<HOST>` / `<PLUGIN_DIR>` 即可。

## 为什么单独讲这一类宿主

它们是最难接的一类，因为有**两个**平台原生概念要翻译，而且很容易做错：

```
宿主自己的插件系统            ← 接入形态该怎么选
宿主自己的 Workspace/Session  ← Agent 与"哪扇门"怎么映射
```

ANP Core 对这两者**一无所知**，也不该知道。

## ① 形态判断

宿主是插件化架构、能力由插件组合、且希望随 Core 启动 →

```
→ Adapter Plugin 形态
  Adapter Plugin 身份：  <ADAPTER_ID>          （约定形如 anp.adapter.<host>）
  Agent 身份：           <AGENT_ID>            （约定形如 <host> / <host>-<instance>）
  delivery mode：        http（插件自己听着 ANP_PLUGIN_PORT 上的 /anp/wake）
```

**不要**为宿主内部的每个插件注册一个 ANP Agent——**宿主插件 ≠ ANP Agent**。
一个 Adapter Plugin 代管一个（或少数几个）Agent 身份就够了。

## ② 对象映射

| ANP 侧 | 这类宿主侧 | 边界 |
|---|---|---|
| Agent identity | 宿主里的一个 Agent 身份 | 一个 Agent 身份 → N 个 Workspace/Session |
| `meta.from_workspace` / `to_workspace` | 宿主的**工作区坐标** | 随信封走，Core 只透传 |
| `correlation_id` / `context_id` | 宿主的**对话线** | ★与 Workspace/Session ID 不是一回事★ |
| delivery mode | 宿主怎么被唤醒 | 靠宿主自己的注入机制 |

### ★最容易做错的一处★

```
✗ 把每个 Workspace 注册成一个 ANP Agent
✗ 把 ANP correlation_id 当成宿主 Session ID 用
✓ ANP Agent → Adapter → 宿主 Workspace / Session（映射留在 Adapter）
```

宿主的**原生 ID 常常是随机值**（例如会话目录名带编码、端口每次随机分配）。
所以：

- **不要把宿主的原生 ID 写进任何静态配置**——它必然过期；
- 需要"我是谁、我在哪个端口"时，**从运行中的实例自报信息里探**，而不是写死。

## ③ Workspace / Session 映射（这类宿主的重点）

```
ANP Agent
    ↓
Adapter（唯一知道"信该投到哪扇门"）
    ↓
宿主的 N 个 Workspace / Session
```

要做四件事：

1. **跟宿主已有机制走**：宿主若已有工作区生命周期、标题、最近使用时间，
   **直接读它**，不要在 ANP 里重造一套。
2. **维护 Agent ↔ Workspace/Session 映射**（Adapter 内部状态，Core 不感知）。
3. **上报名册**：用 `POST /session/roster` 告诉 Core「本地有哪些会话、哪个是用户最近在用的」——
   这是 Adapter 的独有信息源，Core 的会话决策依赖它。名册有 TTL（默认 300 秒），要周期刷新。
4. **回报落点**：执行完新开对话后用 `POST /session/bind` 把 `context_id → session_id` 记回 Core。

### 子项目 / 多工作区的一个常见坑

如果 Adapter 把工作区**写死成某个根目录**，那么子项目发来的信在 Core 眼里也是"根工作区"，
只能匹配到根目录那个正在运行的会话——本该去子项目会话的信会**落进任意一个正在使用的会话**。

**修法（通用机制，不是某家的专用功能）**：让**每个 Adapter 实例声明自己服务哪个工作区**
（例如读一个实例级环境变量 `<HOST>_WORKSPACE`，名字由你定），于是：

- 名册上报的 `workspace`、信封的 `from_workspace`、状态探针的 `config.workspace` 都用它；
- Core 的"精确 / 子目录 / 上级"三档匹配就能把信投进**对应的**会话；
- 不设该变量时退回默认行为（宿主配置 / 进程 cwd）。

> **任何 http 档 Agent 都该声明自己服务的工作区，而不是让 Core 猜。**

## ④ 收信通道要做的三件事

```
① 收 /anp/wake → 校验 x-mailbox-key 是本端 Agent 的令牌
② 照 meta.session 章执行：mode=reuse → 注入该会话；mode=new → 新建会话
③ 返回 {"ok": true, "mode": "<合法值>"}   ← 注入会话 → 用 "session" / "inject"
```

★`mode` 必须是闭集里的精确小写值；只回 `{"ok":true}` Core **不签收**。★

**宿主的注入能力决定 `caps`**（能力广告，Core 不依赖它做基础通信决策）：

```jsonc
"caps": {
  "inject_session": true,    // 能把文字塞进一个已存在的会话
  "spawn_cwd": true,         // 能按 cwd 起新会话
  "resume_session": true,    // 能续接旧会话
  "queue": true              // 能排队
}
```

## ⑤ 模糊寻址：平台信息在 Adapter 侧

宿主的**工作区标题**是最好的候选提示（「发给负责 <某个项目> 的」→ 命中工作区标题含该词的那个）。
但它**不放进 Core**：

```python
local.add(agent_id,
          aliases=["<平台短名>", "<别名>"],     # 平台短名 / 别名
          workspace="<某个工作区标题>",          # 宿主工作区标题
          last_used=time.time(),                # ★平台记录，只有 Adapter 能给★
          tags=["<标签>"])
```

★记 `last_used` 是 Adapter 的责任★：`GET /agents` 只有 `last_seen`（心跳活跃度），
拿它冒充"最近用过"就是撒谎。

## ⑥ 部署路径

宿主 skill / 插件按各自约定安装。**Adapter Plugin 一律装在 `<home>/plugins/<PLUGIN_DIR>/`**，
所以要：

- **vendor 或安装 SDK**——`<repo>/../sdk` 那时不在路径里；
- 用一个 `_find_sdk()` 按「同目录 → 站点包 → 仓库」顺序查找；
- **平台状态放插件自己的 `data/`**，不要写进信箱 `<home>` 根下。

## ⑦ 这类宿主的验收重点

除了通用八项，额外确认：

```
□ 宿主里有 N 个 Workspace/Session 时，ANP 侧仍然只有 1 个 Agent 身份
□ 新开一个宿主会话 → 信能落进去（不是落进"当前正在用的那个"）
□ 已有会话 + 同一条对话线的第二封信 → 回到同一个会话
□ Adapter 重启 → 从 Core 恢复，不依赖宿主原生 ID 的本地缓存
□ 宿主原生会话 ID 是随机值时，重启后仍能路由（不许写死在配置里）
□ 反向链：宿主侧主动发起的回复，能带 reply_to + correlation_id 回到 ANP 原对话线
```

## ⑧ 这类宿主的特征清单（用来判断"我是不是这一类"）

只要宿主同时满足下面两条，就走本文件的形状：

| 特征 | 含义 |
|---|---|
| **有插件系统** | 能力由插件组合、可随宿主启动加载 → 适合 Adapter Plugin 形态 |
| **有多 Workspace/Session** | 一个 Agent 身份对应宿主里多扇"门"，且原生 ID 可能随机 → 映射留在 Adapter |

典型表现（**只作判据，不是产品名**）：

| 项 | 这一类宿主的常见做法 |
|---|---|
| 形态 | Adapter Plugin，http 档 |
| 端口 | 宿主随机端口启动 → 唤醒地址**不能写死**，靠心跳上报 / 运行中探测 |
| 会话坐标 | 会话按工作区编码分目录存放；会话摘要里可读 `cwd` |
| 注入 | 有常驻 HTTP 端点，可把文字注入当前回合 |
| 平台信息 | 工作区标题、最近使用时间都在宿主侧 → 喂给 `LocalDirectory` |
| 实例级工作区 | 用实例级环境变量声明「本实例服务哪个工作区」（子项目分流） |

> 换成任何"有插件系统 + 多 Workspace/Session"的宿主，上面的八步照走，
> 只是宿主 API 的名字不同。

## ⑨ 这类宿主最容易踩的五个坑

1. **为每个 Workspace 注册 Agent** → ANP 名册被宿主内部对象淹没。
2. **把宿主原生 Session ID 当 `correlation_id`** → 两层概念混用，回信落错门。
3. **把 Adapter 绑死在某个根工作区** → 子项目的信落进任意会话；要声明实例级工作区。
4. **写死随机端口 / 随机会话 ID** → 重启即失效；要从运行实例自报信息里探。
5. **`on_wake` 返回时忘了合法 `mode`** → Core 不签收，信被反复重投。
