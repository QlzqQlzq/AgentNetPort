# 验收与缺口

## 一、两条链都要证明

```
正向：Core → Adapter → Agent → 平台 Workspace / Session

反向：平台 Workspace / Session → Adapter → ANP Envelope → Core → 其他 Agent
```

**两条都通了才算接入成立。**

## 二、必测八项

| # | 场景 | 期望 |
|---|---|---|
| ① | 精确 Agent ID | `RESOLVED (decided_by=exact)` → 发得出去 |
| ② | 模糊目标且唯一 | `RESOLVED` |
| ③ | 模糊目标多候选 | `AMBIGUOUS` + `candidates`（**不含 target**，不自动挑） |
| ④ | 不存在目标 | `NOT_FOUND`；空目标 → `INVALID_TARGET` |
| ⑤ | 新 Workspace / 新 Session | **⑤a** 照 Core 的 `meta.session` 章执行 `new`（必测）；**⑤b** 有会话通道时 `POST /session/bind` 回报落点（无则 SKIP 并写原因） |
| ⑥ | 已有 Workspace / 已有 Session | 照章执行 `reuse`（优先 `context_id` 绑定；其次按 Core 盖章结果）——**判定不在 Adapter 重做** |
| ⑦ | Adapter 重启后的恢复 | **⑦a** 凭证仍在时进程重启 → 同一 token 续约、wake 更新到新端口（必须过）；**⑦b** 凭证全丢 → 预期 401 / 不假装 bootstrap（v0.1 限制，见下） |
| ⑧ | ANP 消息回复 | 回信带 `reply_to` + `correlation_id`，回到原对话线 |

### ⑤⑥⑦ 的特别提醒

- **⑤/⑥ 的判定不要自己实现**——Core 盖 `meta.session` 章，你照章执行 `reuse` / `new` 即可（读信封字段，**不算**新 API）。
- **`/session/roster`、`/session/bind` = 通道扩展面（可选）**，不是六件套。资格线「只用 canonical API」= 六件套 ∪ 已声明的通道扩展面。无 Workspace/Session 的通道对 ⑤b 显式 SKIP。
- **⑦a（进程重启）是"硬规则"在 v0.1 的可执行形式**：凭证在插件 data/ 时，杀进程 → 重启 → 同一身份续约、wake 指新端口。
- **⑦b（凭证全丢）与 P0-2 互斥**：清掉本地 token 后无钥续约必 401，且**不得**用重铸/admin 绕过。v0.1 预期行为 = 拒绝且不静默换身份；真·无钥恢复另立项（recovery nonce），不在本期。

## 三、自检清单（逐条过）

```
身份
  □ Adapter Plugin 身份与 Agent 身份是两个不同名字、两枚不同令牌
  □ Agent 令牌只在投递/收发时用；plugin 令牌只用于 /plugin/register

寻址（可选，做了就逐条过）
  □ 精确 Agent ID → RESOLVED，且不会再去匹配别人
  □ 候选唯一 → RESOLVED；多个相近候选 → AMBIGUOUS + candidates（★不自动挑★）
  □ 没有任何匹配 → NOT_FOUND
  □ last_seen 只用于排序；last_used（平台记录）才可破并列，差距不足时仍 AMBIGUOUS
  □ 候选视图分开回报 last_used / last_used_source / last_seen（★不互相顶替★）
  □ resolve 与 send 的失败分得开（"不知道发给谁" ≠ "投不出去"）
  □ 解析只用公开名册 + 本地平台提示；没有把平台语义塞进 Core

注册
  □ 首次 POST /heartbeat 无密钥能拿到 key
  □ 第二次同名字无密钥 → 401（不是重新发 key）
  □ 同名字 + 正确 key → 200 续约
  □ 不带 wake 的续约心跳不会抹掉既有 wake 端点
  □ wake: null 能主动清掉端点

唤醒（按你选的档位）
  □ http：/anp/wake 收到 {"message":…,"to":…}，x-mailbox-key 里是 Agent 令牌
  □ http：★响应含合法 mode；仅 {"ok":true} 不算签收★
  □ exec：子进程能从 AGENT_ANP_WAKE_JSON / SELF / SELF_KEY 三项环境变量拿到信封
  □ queue：agent 能自己 POST /messages/receive 取到信

接口
  □ 只用 §6.1 那 6 个 Core API，没有读任何 Core 内部文件
  □ 没有出现过 hub signing secret
  □ /send 已换成 /messages/send

状态
  □ 没有向 Core 上报过 {"status": "online"} 这类复合状态
  □ 没有从 liveness 推导 reachability，或反之

收发闭环
  □ 收信 → 平台处理 → 回信，回信带 reply_to + correlation_id
  □ 把一封信的 body 改一个字，你的回信仍然发得出去（信封签的是正文）
  □ need_reply=true 才要求回信；缺省为知会（S4）
  □ 平台执行失败有补偿（S3），不是只写 log
```

## 四、"通过"不等于"看起来没报错"

| 错误判据 | 为什么不算 |
|---|---|
| `ok=true` | 只表示**已持久化**，不代表对端收到或消费 |
| HTTP 2xx | 唤醒响应还要 `ok:true` **且** 合法 `mode` 才算签收 |
| "注册成功" | 注册 ≠ 通了；要看 `wake` 字段与消息记录状态 |
| `{"status":"online"}` | Core **不定义**统一 `status`；只有 liveness / reachability / lease 三个独立事实 |
| Agent 自己"感觉收到了" | 要证明的是**信封到了正确的会话**，并有回信闭环 |

**正确读法**：

```
wake 字段             → 本次投递结果（ok / kind / error）
消息记录状态字段       → delivered_at / attempts / next_retry_at / last_error / read / wake_skipped
queue 档终态          → attempts=0、next_retry_at=None、不触发 message.undelivered、
                        wake_skipped="no_push_target"
```

## 五、缺口记录模板

**先记录缺口 + 证据，不要擅自扩大 Core。** 按四类归类：

```markdown
### [类] 一句话缺口

- 现象：（命令 + 真实输出）
- 复现：最小步骤
- 影响：谁会踩到、踩到后什么表现
- 我的绕法：（如果有）
- 建议归属：Core / Spec / SDK / Adapter
```

四类：

| 类 | 含义 | 处理 |
|---|---|---|
| **Core** | Core 实现的行为与规范不符 / 缺能力 | 记录，**不擅自改** |
| **Spec** | 规范没写清 / 写错 | 记录，确认是规范错误才另开变更 |
| **SDK** | SDK 实现与 Spec 不一致 | **改 SDK，不改 Spec** |
| **Adapter** | 自己写错了 | 自己改 |

### 已知的真实缺口（照抄，别重复踩）

| 类 | 缺口 |
|---|---|
| **Core** | `install_roots()` 不含 `<home>/plugins/` → 真实部署下 Plugin 的 `exec` 唤醒一律被拒 |
| **Core** | 插件启动预算只有 10 秒，超时报「端点不可达」——指向错误方向（插件其实只是慢） |
| **Spec** | 没约定 Adapter 的平台状态该放哪（建议放插件自己的 `data/`，别写进信箱 home） |
| **SDK** | `PluginServer` 曾静默吞掉 `on_register` 的异常 →「adapter 正常但代管 agent 不存在」最难查 |
| **Spec** | `register=allowlist/closed` 会让**所有** Adapter Plugin 一起失效（待补正式机制） |
| **Spec** | `agents.discover` 是死权限（`/agents` 实际免令牌）；决定前**以代码为准（公开）** |
| **Adapter** | 唤醒用协议里不存在的 `{prompt}` 占位符（Core 原样透传，于是那档可能从未生效） |
| **Adapter** | 直接读 Core 内部（`core.read_records` / `core.agent_table`），违反 Spec §1 |
| **Adapter** | 平台状态写进信箱 `<home>` 根下 |
