## 0. 为什么是 v0.1.1，不是 v0.2

架构方向仍成立：

- Core 负责通信，不负责应用语义（大体成立；会话决策见债务区）
- Adapter Plugin = 代管 + 翻译（定义正确）
- 三档 delivery / 三事实分离 / sticky / P0-0 queue 终态（方向正确）
- SDK 不 import Core、Reference 可藏 `src/` 运行（资格线真实）

冻结后暴露的是**实现级裂缝**：Spec 教第三方写错、鉴权被抬高、exec 投递语义过早、关键安全不变量测试假绿。  
这些修完就能继续迁真实 Adapter，不需要推倒模型。

### B1 · HTTP wake 响应必须写明 `mode` 契约

| 项 | 内容 |
|---|---|
| **分级** | P0（规范可实现性） |
| **现象** | Adapter Spec §5.1 / §10 教第三方 `return {"ok": true}`；Core `wake_sign_off_ids` 要求响应含非空 `mode` 才签收。 |
| **证据** | `docs/ANP-ADAPTER-SPEC.md` §5.1 / §10；`src/anp_core.py` `wake_sign_off_ids`（http 档无 `mode` → 不签收）；LOGIC/PROTOCOL §4.2.2 写了 `mode`，Adapter Spec 没写。 |
| **后果** | 第三方只读 Adapter Spec 实现 http 档 → 信永不签收、未读悬挂、可能被再推。 |
| **修法（最小）** | **只做契约补全，不改 wake 状态机。** 权威文本已定稿：`docs/ANP-ADAPTER-SPEC-ERRATA-V0.1.1.md`（B1）。合入锚点见该文件 §B1.8；实现/测试对齐见 §B1.9–B1.10。 |
| **响应契约（已定稿）** | `{"ok": true, "mode": "<响应模式>"}`。`mode` ∈ `immediate` \| `batched` \| `session` \| `inject` \| `followup`（闭集）。**仅 `{"ok":true}` 不构成签收**；HTTP 2xx ≠ 签收。`mode` **不得**表示 delivery mode（`http`/`exec`/`queue`）。 |
| **验收标准（B1 DoD）** | 见 errata §B1.10：Spec 合入 + §10/§11 同步 + Reference/SDK 默认带合法 `mode` + 三类测试（ok+mode 签收 / ok 缺 mode 不签收 / 200+ok=false 不签收）且负例可红 + 未改 retry/请求载荷/delivery mode。 |
| **涉及文件** | `docs/ANP-ADAPTER-SPEC.md`、`examples/adapter_demo/*`、`examples/adapter_plugin/*`、`sdk/anp_adapter/{transport,plugin}.py`、`tests/`（新增 B1 用例） |
| **明确不改** | Core 签收判据本身（保持 `mode` 非空才签收） |

### C1 + B2 · 鉴权模型最小化（合并处理）

| 项 | 内容 |
|---|---|
| **分级** | C1 = P0/P1 边界，**按 P0 处理**；B2 = 并入本项 |
| **现象** | ① `/plugin/register` 实际要 **admin token**，Spec 2b 却写「Plugin token 只用于 `/plugin/register`」；admin 能看全部正文（`/sessions`、看板）。② Spec §3.2 写「已有 name + 管理员令牌 → 放行」，实现对已有身份只认身份密钥（`_auth`/`verify_key`），admin **不能**续约。 |
| **证据** | `src/anp_hub.py` `/plugin/register` → `self._admin_ok()`；`sdk/anp_adapter/client.py` `plugin_register(..., admin_token)`；`examples/adapter_plugin/experiment.py` 读 `core.admin_token`；`docs/ANP-ADAPTER-SPEC.md` §2b / §3.2；`docs/ANP-PLUGIN-SPEC.md` §4.0。 |
| **后果** | 身份分层被击穿：要么插件拿不到报到权，要么持有全局 admin（违背最小权限）。文档与实现在续约路径上互相矛盾。 |
| **先定能力，再定令牌（禁止拍脑袋）** | `/plugin/register` 只需要：**证明请求来自某个已加载 Plugin，并允许它更新自己的注册声明（tools/events/panel）+ 取回自己的凭证。** 不需要读他人消息、不需要管其他插件、不需要铸造身份。 |
| **推荐修法（鉴权最小化，不重做权限体系）** | **方案 P（推荐）**：`/plugin/register` 改为鉴 **插件自己的 agent token**（`verify_key(pid, x-mailbox-key)`）；或 Core 在 `/anp/register` 下发的 **register nonce**（一次性/可轮换，仅能报到自己）。**禁止**把 `admin.token` 交给任何 Adapter/Plugin。 |
| **备选** | 若短期必须兼容：保留 admin 旁路但 **文档降级为「仅运维/接线脚本」**，SDK 默认不暴露 admin 参数，并标 deprecated。不推荐长期保留。 |
| **B2 对齐** | Spec §3.2 与实现二选一对齐。**推荐改 Spec**：已有身份只认身份密钥；admin **永不**能续约/顶替他人身份（与 P0-2 一致）。删除「已有 name + 管理员令牌 → 放行」这一行。 |
| **验收标准** | ① 插件进程**仅持有自己的 plugin/agent token** 能完成 `/plugin/register`（重启报到）；② 拿 admin 调 `/plugin/register` 的行为有明确测试（拒绝或仅运维路径，与文档一致）；③ 插件响应体仍不含 `hub.secret`；④ Spec 2b / §3.2 / §4.0 / SDK 签名四处一致；⑤ 负例：用 A 插件 token 报到 B 插件 → 拒绝；⑥ experiment 不再依赖 `core.admin_token` 完成报到（或注明仅测试夹具）。 |
| **涉及文件** | `src/anp_hub.py`、`src/anp_plugin.py`、`sdk/anp_adapter/client.py`、`docs/ANP-ADAPTER-SPEC.md`、`docs/ANP-PLUGIN-SPEC.md`、`examples/adapter_plugin/*`、`tests/selftest_plugins.py` |
| **明确不改** | 不做完整 RBAC；不给 Plugin 发新 permission 枚举；不动 hub.secret 隔离。 |

**目标身份图（修完后）：**

```text
hub.secret          → 仅 Core 签名
plugin credential   → 仅证明「我是这个 Plugin」（报到 / 收 /anp/register）
agent token         → 仅代表某个 Agent 收发
admin token         → 仅管理员（面板 / sessions / 运维），不进 Adapter
```

### D1 · exec `delivered_at`：先实证，再最小修

| 项 | 内容 |
|---|---|
| **分级** | P0（大概率成立；**禁止未实证就改状态机**） |
| **现象（待证）** | `core.wake` exec 档 `Popen` 成功即 `{"ok":true}`；`record_delivery` 据此写 `delivered_at`；`auto_redeliver` 只重投 `delivered_at` 为空的信。子进程若立刻崩溃且未处理，信可能成为「已投递未读」且**永不自动重投**。 |
| **证据（代码）** | `src/anp_core.py` `wake()` exec 分支返回 pid 即 ok；`wake_sign_off_ids` 对 exec 故意不签收；`src/anp_hub.py` `deliver_one` 用 `outcome.ok` 记账；`auto_redeliver` 过滤 `delivered_at`。 |
| **第一步：最小实验（必做）** | 见下方实验脚本意图。记录：`attempts` / `delivered_at` / `next_retry_at` / `read` / `last_error` / 一轮 `auto_redeliver` 是否动作。 |
| **判定** | 若 `delivered_at != null` 且后续 `auto_redeliver` **永不**重投 → 实锤，进入修复。 |
| **修法（最小，禁止顺手大改）** | **推荐语义补丁**：exec 档 spawn 成功 **不写** `delivered_at`；只写 `last_attempt_at`（+ 可选 `spawned_at`/`wake_pid`）。`delivered_at` 仅在「唤醒器 `mail_ack` / 约定落地」时写。`auto_redeliver` 条件从「未 delivered」改为「未 ack 且到期」时，**只动 exec 档判定**，http/queue/skipped/no_push 行为保持不变。 |
| **备选（更小）** | 保持 `delivered_at` 字段名，但 exec 写入改为「ack 后才写」；或新增 `acked_at` 且 auto_redeliver 看 `acked_at`（http 已有 read/签收路径，注意别双轨）。**不**把状态机改成完整 `spawned/attempted/acked` 三字段模型，除非实证后发现两字段不够。 |
| **验收标准** | ① 实验记录存档（表：时间线 + 四字段）；② 修复后：exec 子进程立即退出 → `delivered_at` 为空（或 `acked_at` 为空）→ `auto_redeliver` 会再拉起；③ exec 正常处理并 ack → 不再重投；④ http / queue / `wake=false` / `no_push` 回归全绿（行为不变）；⑤ Spec §4.2 / §9 / §5.4 对「ok / delivered / acked」用词与实现一致。 |
| **涉及文件** | `src/anp_core.py`（`record_delivery` / `wake` / `wake_sign_off_ids`）、`src/anp_hub.py`（`deliver_one` / `auto_redeliver` / `do_redeliver`）、`docs/ANP-ADAPTER-SPEC.md`（§4/§5.4/§9）、`tests/`（新增 D1 用例） |
| **明确不改** | queue 终态（P0-0）、三态 `wake_skipped`、http 签收 `mode` 判据、退避公式、max_attempts 策略（除非实证证明不够）。 |

**最小实验意图（执行时用）：**

```text
1. 注册 exec Agent，wake.command 指向「立刻 exit(1) 且不读环境」的脚本
2. POST /messages/send 一封信
3. 立刻读收件箱状态：attempts / delivered_at / next_retry_at / read / last_error
4. 跑一轮 auto_redeliver（或等扫描线程）
5. 再读同一封
6. 对照组：脚本正常处理并 mail_ack → 确认不会被再投
```
