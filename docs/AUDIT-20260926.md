## 1. 已确认并修复的问题

### 1.1 执行❶ exec 信任根可被绕过 → **成立，已修**（P0）

复现（修复前，`core.check_wake_config`）：

| 命令 | 旧结果 |
|---|---|
| `python -c "<任意代码>" <任意可信路径>` | ✅ 放行（真正执行的是 `-c` 的正文） |
| `python -m http.server <任意可信路径>` | ✅ 放行 |
| `python -c "<任意代码>" <**不存在**的可信路径>` | ✅ 放行 |
| 相对脚本 + `cwd` 指向别处 | 按 hub 进程 cwd 判过，实际在别处跑 |

根因：旧规则是"argv 里**任意一个**像路径的参数命中信任根就放行"，
既没认"哪个参数才是被执行的脚本"，也没看 `argv[0]`。

**报告外还发现一个更直接的旁路**：`argv[0]` 完全不被校验，
于是 `["/tmp/evil.exe", "<任意可信路径>"]` 也能过——而 `Popen` 执行的正是 `argv[0]`。

修法（`anp_core._check_exec_command`，三层）：

1. **开关层**：内联执行开关（`-c` / `-e` / `-m` / `--eval` / `/c`）与
   按路径再加载代码的开关（`-r` / `--require` / `--import` / `--loader`）→ 一律拒绝；
2. **argv[0] 层**：解释器（`python` / `node` / `bun` / `deno` / `cmd` / `powershell` /
   `bash`…，认名字不认路径）或安装目录内的可执行文件；其它一律拒绝；
3. **脚本层**：第一个带源码扩展名的参数（没有则退回第一个像路径的参数）必须在信任根内，
   它之后再出现"像代码"的参数也要在信任根内。

相对路径一律按 `wake.cwd`（实际执行目录）解析，不再按 hub 进程 cwd 猜。

**没有误伤合法配置**（这一点是实测逼出来的，不是想当然）：第一版收紧成
"每个像路径的参数都要在信任根内"，立刻把 G1 的 `dump.json` 与 demo adapter 的
`--hub http://127.0.0.1:PORT` 当成脚本拒掉（3 个套件翻红）。所以规则必须分
"开关 / argv[0] / 被执行的脚本 / 数据参数"四类看，数据参数不参与校验。
现在的覆盖：审计的 4 条绕过 + 报告外 3 条旁路全部拒绝，7 条合法写法全部放行
（`tests/selftest_audit_20260926.py` A1.1–A1.15）。

### 1.2 执行❷ 身份名清洗造成收件箱碰撞 → **成立，已修**（P1）

复现（修复前）：`_safe("a/b")`、`_safe("a:b")`、`_safe("ab")` **全是 `ab`**；
实测 `ab` 身份能读到 `a/b` 与 `a:b` 的信（2 封），可签收、可重投。

修法：`_safe()` 从"过滤"改成**编码**（单射）：不认识的字符按 UTF-8 字节百分号转义，
`%` 自己转 `%25`。`a/b → a%2Fb`、`a:b → a%3Ab`、`ab → ab`，三者互不相同。
只含 `[字母 数字 -_.@]` 的名字（现有全部身份）**输出一字不变**，老收件箱文件照旧命中
——这一点对线上数据是关键：live home 的 7 个收件箱名字全都在这个集合里。

配套两处：
- `known_inboxes()` 解码回原始身份名（`/agents` 不再显示编码名）；
- `POST /heartbeat` 现在**拒绝**含编码字符集之外字符的身份名（400，
  审计报告说的"Hub 注册接口没有执行同等约束"）。

顺带修了一个同源bug：`prune()` 用 `p.stem` 当身份名去读，会被二次编码
（`a%2Fb` → `a%252Fb`），读到另一个文件；现在先解码再读。

### 1.3 执行❸ correlation journal 碰撞 → **成立，已修**（P1）

复现（修复前）：`journal_path("game/1") == journal_path("game1")`（都是 `game1.jsonl`）；
两条线的信写进同一个文件，`journal_owner` 返回第一个发送者 `alice`，
于是 `carol` 建的线也归 `alice` 所有——授权判据本身被污染。

修法：`_safe_correlation()` 复用同一个单射编码（本来就是调 `_safe`，一行生效）。
修后两条线各自成文件、各自记 owner（`game1 → carol`，`game/1 → alice`）。

### 1.4 执行❹ 插件权限声明基本未执行 → **成立，已修**（P1，一处按 Spec 边界处置）

复现（修复前）：权限闭集 5 个，只有 `webui.panel` 在 `/admin/panel` 有检查。
实测 `permissions: []` 的插件照样能把工具塞进 agent 可见 API。

修法（`docs/ANP-PLUGIN-SPEC.md` §5.1 是唯一执行点清单）：

| 权限 | 执行点 | 效果 |
|---|---|---|
| `tools.register` | `plugin.tool_registry()`（`/tools` 与 `/tool` 共用） | 工具不进注册表，与"没有这些工具"不可区分 |
| `wake.others` | `do_send` / `send_group` 出站前 | `wake=true` → `permission.denied` |
| `broadcast` | 同上，判据是收件人 > 1 | 多收件人 → `permission.denied` |
| `webui.panel` | 原有 | 403 |
| `agents.discover` | `/tool` 的 `mail_agents` | `permission.denied` |

只对**已加载插件身份**查表（`plugin.permissions_of()` 返回 `None` 表示不是插件）：
各 Adapter 代管的 agent 与 MCP 客户端是普通身份，不受影响。这不是偷懒——
把普通身份也纳入插件权限，会一次性打断整个接入生态（4 个 Adapter 的代管身份都在发信）。
实测确认 4 个 Adapter 全部以**代管身份**发信（`as_identity(agent_key, MANAGED_AGENT)`），
不受本闸影响。

`agents.discover` 的报告内期望（"`/agents` 不检查 agents.discover"）**按 Spec 既有裁定
另行处置**，见 §4.7。

### 1.6 执行❻ compact_ledger() 会丢并发 heartbeat → **成立，已修**（P1）

复现（确定性）：在"读完账本"与"加锁替换"之间的窗口里落一条新心跳
（用 monkeypatch 放大既有窗口，不制造新行为），压缩后该身份最新心跳**被抹掉**
（`note` 回到旧值）。根因：`rows = read_ledger()` 在锁外，`with _mutation_lock` 直到
替换前才拿。

修法：读-改-写整段放进 `_mutation_lock`（与 `prune()` 同一写法）。
heartbeat 的 `append_line` 在此期间等锁，不再被旧快照覆盖。
复测：同一条竞争下新心跳存活；正常压缩语义不变（每身份留最后一条 + 最近 N 行）。

### 1.7 执行❼ HTTP 请求体和长轮询可耗尽服务 → **成立，已修**（P1，两处）

复现（修复前，实测）：

| 输入 | 旧行为 |
|---|---|
| `Content-Length: abc` | `int()` 抛 ValueError，调用点只接 `BadBody` → 异常冒到 socketserver，客户端看到**连接被重置**，不是 400 |
| `Content-Length: -1` | `rfile.read(-1)` = 读到 EOF 为止 → 连接不关，请求线程**一直挂起**（实测等到超时） |

修法：
- `_body()`：`content-length` 非整数 / 负数一律 `BadBody` → 结构化 400；
- `do_wait()` 加**并发名额**（`AGENT_ANP_WAIT_MAX`，默认 32）：满了回 `wait.busy`
  让调用方重试或改 `mail_inbox` 轮询，不再无限堆线程；当前占用在 `/health.wait` 可见
  （原来 `INFLIGHT` 只服务于优雅停止，不做限流，这一点报告说得对）。

> 说明：`timeout_sec` 上限仍是协议写定的 900 秒，**没有单方面改协议**。
> 改的是"同时能挂几个"，不是"一个能挂多久"。

### 1.8 执行❽ 管理员 token 可进入访问日志 → **成立，已修**（P1）

复现（修复前，实测）：`GET /sessions?token=SUPERSECRET-TOKEN-123` → 401，
而 `<home>/logs/hub.log` 里出现 `"GET /sessions?token=SUPERSECRET-TOKEN-123 HTTP/1.1" 401`。
`?token=` 是看板（浏览器）的用法，堵不掉，那就**打码**。

修法：`Handler.log_message()` 落盘前把查询串里的 `token` / `key` / `secret` /
`password` 的值换成 `***`。修后日志行变成 `"GET /sessions?token=*** HTTP/1.1" 401`
——请求行仍然可读，令牌不再外泄。

### 1.8a 追加：hub 启动时把整枚管理员令牌写进 hub.log → **成立，已修**（P1）

同一类残留的另一半：访问日志堵住了，但启动日志自己又把**整枚**管理员令牌
原样写进 `<home>/logs/hub.log`（"打印一次，方便第一次进看板时抄"）。
那枚令牌能读全部 agent 通信，而 hub.log 会被 `spawn_hub` 重定向、会被人贴进
issue、会被同步工具搬走——2019 年那种"把钥匙贴在门外"的现代版。

修法（2026-09-26）：启动行只打**前 8 位**，并指向完整令牌的唯一位置
`<home>/admin.token`（该文件权限已收紧到仅本人）。同时把当时日志里
已经写下的完整令牌替换成 `前8位…（已脱敏）`，确认日志中不再出现任何
48 位令牌。新启动行形如：
`[hub] 管理员令牌（…）：c737eb61…（只显示前 8 位；完整令牌在 …\admin.token）`

`看板伴生：找不到 <ANP_ROOT>\src\mailbox_webui.py，跳过`

## 2. 部分成立 / 按 Spec 边界另行处置的问题

### 2.1 执行⓭ 条件性 P1：WebUI 可泄露管理员 token → **成立，已修**（含一项超出报告的发现）

复现（修复前，实测）：`GET /_anp/session` **无任何鉴权**返回
`{"adminToken": "local-admin-token", ...}`，且那枚令牌对**线上 hub（8900）真的有效**
（`/admin/messages` 200）。默认绑回环，但 `--host 0.0.0.0` 时局域网可直接取。
另外 `AGENT_ANP_HUB_URL` 指向任意远程地址时，本地令牌会被明文发过去。

修法（`webui/desktop.py`）：
- `/_anp/session` 只发给**回环客户端**（判据是 socket 对端地址，不是 `Host` 头），
  非回环一律 404；
- `admin_token_works()` 非回环 hub 一律拒绝发送本地令牌；
- 用**猜出来的缺省令牌**能进时打一条 warning（见下）。

**超出报告的发现**：live home 的 `admin.token` 内容就是字面量 `local-admin-token`——
一个公开常数，而桌面壳的候选列表里就有它。任何能连上这个端口的进程都能想到这枚令牌。
本轮**没有替用户改这个令牌**（改了会让他眼前的看板掉线），只在猜中时提醒一次。
建议主人找时间换掉：写一串随机值进 `<home>/admin.token`，重启 hub，刷新窗口。

### 9.4 ★本轮最大发现：三个适配器凭证丢失，代管身份不可达（P0）★

这不是审计报告里的项，是 live 巡检发现的。**在 09-25 18:33 就存在，与本次改动无关。**

现象：`codex` / `chencode` / `mimo` 的身份记录里 wake 指向 09-25 的旧端口（59971/59966/59982，适配器早不在那），
发往这三个身份的信会唤醒失败 → 重投 → 放弃。

根因：三个适配器的 `<home>/plugins/<id>/data/` 是**空的**（没有 `<name>-credentials.json`）。
凭证一丢，重启后 `bootstrap()` 不带密钥，而身份已在 `keys.json` 里 → 被 P0-2 的正确规则挡成
`401 missing` → **永久锁死**。适配器自己的日志从 09-25 18:33 起每几分钟记一次 register failed
（mimo 曾在启动时空转重试 40 次）。对照组 `dsh` 有 `data/dsh-credentials.json`，所以它一直正常。

恢复动作（写凭证 → 受控 reload，一个一个来）：

1. 从 `keys.json` 取这三枚身份**已有的**令牌（没有新造、没有更换），按适配器自己的
   `save_credentials` 格式写进各自 `data/<name>-credentials.json`，并用 `core._tighten` 收紧权限；
2. 逐个 `POST /plugins/<id>/reload`（带新 admin 令牌）。

| 检查点 | 结果 |
|---|---|
| wake 端点更新 | 59971/59966/59982 → 50995/63944/51013（各指自己插件当前端口） |
| 可接收信封 | 平台进程是活的（ChenCode ×4、codex ×1），所以**不能**打 `wake=true`（会把消息灌进你正在跑的会话）。改用零副作用探针：错钥匙 → 拒；对钥匙 + 缺 `body` → 过鉴权但拒收，且协议要求的 `mode` 在场。三个全过 |
| `wake=false` 缓存信 | 三个各一封落盘，`read_by=cache:silent-delivery`、`wake_skipped=True`、`attempts=0`（按设计不唤醒） |
